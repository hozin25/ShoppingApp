## 1. 项目概述

### 1.1 目标
对 uni-mall 小程序移动端进行全面的UI美化升级,采用现代简约(Apple/小米)设计风格,提升用户体验和视觉品质。

### 1.2 范围
- **改造范围**: 仅前端UI和样式,不修改后端代码,不影响现有功能
- **优先级**: 核心页面优先改造
- **改造方式**: 轻量级样式改造方案(方案一)

### 1.3 核心页面清单
1. 首页 (`pages/index/index.vue`)
2. 商品列表页 (`pages/shangpin/list.vue`)
3. 商品详情页 (`pages/shangpin/detail.vue`)
4. 购物车页面 (`pages/cart/list2.vue`)
5. 订单确认页 (`pages/shangpinOrder/confirm.vue`)
6. 用户中心页 (`pages/center/center.vue`)
7. 登录/注册/忘记密码页面
8. 商家列表页
9. 论坛列表页
10. 公告列表页

- 超小间距: 8rpx

- 卡片阴影: `0 2rpx 16rpx rgba(0,0,0,0.04)`
- 悬浮阴影: `0 8rpx 24rpx rgba(0,0,0,0.08)`
- 按钮阴影: 无(使用纯色背景)

### 2.6 透明度层级

- 禁用状态: 0.4
- 次要文字: 0.6
- 遮罩层: 0.5

## 3. 页面详细设计

### 3.1 首页

**布局结构**:
```
┌─────────────────────────┐
│   状态栏 + 导航栏(白色)   │
├─────────────────────────┤
│   搜索栏(圆角胶囊)        │
├─────────────────────────┤
│   轮播图(圆角卡片)        │
├─────────────────────────┤
│   快捷菜单(2行4列网格)   │
├─────────────────────────┤
│   公告区(简洁列表)       │
├─────────────────────────┤
│   商品推荐(瀑布流卡片)   │
├─────────────────────────┤
│   商家推荐(横向滚动)     │
└─────────────────────────┘
```

**关键改造点**:
- 移除Tesla风格的大标题,改用简洁的小标题
- 轮播图改为圆角卡片(16rpx),无边框
- 菜单图标使用扁平化设计,图标+文字垂直布局
- 公告区简化为带小圆点的列表项
- 商品卡片:大图(占卡片70%) + 商品名称 + 价格(红色,32rpx)
- 移除所有彩色边框,使用白色卡片 + 浅灰背景分隔

**商品卡片样式**:
```css
卡片: 白色背景, 16rpx圆角, 极简阴影
图片: 圆角12rpx, 宽100%, 高度固定
商品名: 28rpx, 2行省略, 深灰黑
价格: 32rpx, 红色, 粗体
```

### 4.2 样式迁移策略

为确保不影响现有功能,采用以下策略:

**1. 保留所有功能性代码**
- 所有 `data()`、`methods`、计算属性保持不变
- 仅修改 `<template>` 的class名称和结构
- 仅修改 `<style>` 的CSS代码

**2. 渐进式样式替换**
- 新样式使用新的class名称(如 `.apple-card`、`.modern-btn`)
- 旧样式class保留,逐步移除
- 确保新旧样式不冲突

**3. CSS作用域隔离**
- 每个页面的样式使用 `scoped`
- 设计令牌使用全局CSS变量
- 避免样式污染

**4. 测试点**
- 每完成一个页面,在微信开发者工具中测试
- 验证所有交互功能(点击、滑动、输入等)
- 检查不同屏幕尺寸的适配
- 确认API调用正常

### 4.4 风险控制

**主要风险**:
1. 样式改动导致布局错乱
2. 功能性代码被误改
3. CSS变量在不同平台兼容性问题

**应对措施**:
1. 每改一个页面立即测试
2. 使用git分支开发,保留原始代码
3. CSS变量使用uni-app支持的语法
4. 优先在H5端测试,然后在小程序端验证
